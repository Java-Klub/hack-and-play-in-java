12.2 Report a failed operation

Sharing twelve tokens among zero players has no useful answer. Returning zero would hide the mistake as if a calculation had succeeded. An exception reports that the requested operation could not produce its normal result.

Run the example with 3, 0 and three. Watch which message appears; each run follows only one of the three paths.

int share(int tokens, int players) {
    if (players < 1) {
        throw new IllegalArgumentException("Players must be positive.");
    }
    return tokens / players;
}

void main() {
    String reply = IO.readln("Players: ");
    if (reply == null) return;
    try {
        int players = Integer.parseInt(reply.strip());
        IO.println("Each gets " + share(12, players) + ".");
    } catch (NumberFormatException failure) {
        IO.println("Use a whole number.");
    } catch (IllegalArgumentException failure) {
        IO.println(failure.getMessage());
    }
}

throw new IllegalArgumentException(...) creates a failure with an explanation and throws it to the caller. The remaining lines in share are skipped. There is no returned token count on that path.

A try block marks work whose failure you want to handle. Java looks for a matching catch. Its parameter receives the exception object; getMessage() reads the explanation. After handling it, execution continues after the complete try/catch statement.

NumberFormatException is a more specific kind of IllegalArgumentException. Put its catch first. Reversing these two catches would make the specific one unreachable. Avoid catching every possible exception just to print a success message.

Trace a typo and a forbidden number

For three, parsing throws before share runs. For 0, parsing succeeds, but share throws. For 3, share returns four and no catch runs. What happens for -2?

A catch does not repeat the failed statement. Giving the player another attempt requires a surrounding loop.

Task: a volume reader with a contract

Finish readVolume in code/VolumeReader.java. Accept integer text with outer spaces and return only values from zero through ten. For a number outside that range, throw an IllegalArgumentException with the exact message Volume must be 0..10..

Keep the supplied typo handling. Check 0, 10 , -1, 11 and loud. Only valid numbers reach the success print.

Hint 1: do not lose conversion failures

Keep parseInt. Add a range guard after it and before returning its result.

Hint 2: refusal is not a volume

Use throw new IllegalArgumentException(...) for the out-of-range branch. Do not return a substitute value.
