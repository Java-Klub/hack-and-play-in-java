12.3 Let the player correct a reply

A mistyped number should not force someone to restart the whole program. Combine the loop you know with a narrow catch: ask, attempt one conversion, and ask again only when that attempt fails.

Run the example and enter ten, 0 and 4 on three separate lines. It explains each refusal and finally accepts four. Entering q stops the conversation.

void main() {
    while (true) {
        String reply = IO.readln("Code length: ");
        if (reply == null || reply.strip().equalsIgnoreCase("q")) {
            IO.println("Stopped.");
            return;
        }
        try {
            int length = Integer.parseInt(reply.strip());
            if (length < 1 || length > 8) {
                IO.println("Use 1..8.");
                continue;
            }
            IO.println("Ready: " + length);
            return;
        } catch (NumberFormatException failure) {
            IO.println("Use a whole number.");
        }
    }
}

The input call belongs inside the loop. Reading once before it would leave the same bad reply stored forever. Each new iteration must obtain fresh text.

continue skips the remaining body and begins the next iteration. return ends main completely. After a caught typo, execution reaches the loop end and repeats naturally; no extra recursive call is needed.

A closed input supplies null, while Enter alone supplies empty text. The example stops for null and q, but treats an empty line as another failed number. Check for null before calling String operations.

Predict a short conversation

For inputs 9 then 2, the first reply prints Use 1..8.; the second prints Ready: 2 and ends. What happens for a typo followed by q?

Task: finish one booking, not several

The supplied code/TicketRetry.java reads only once. Rebuild its main so it asks again after a typo or a number outside one through six. Keep the supplied readTickets contract and both different error messages.

A successful booking prints exactly one confirmation and ends. q and closed input print Stopped. and end. Try 0 then 2, a blank line then 6, and many then q. No rejected attempt creates a booking.

Hint 1: move the whole attempt

Repeat the prompt, stop check and try/catch together. Do not repeat only the parser.

Hint 2: choose the exit point

Use a return immediately after the success message. The catch blocks should allow the surrounding loop to continue.

The same distinction between a valid result and a failed attempt also matters when the reply comes from a file rather than a person.
