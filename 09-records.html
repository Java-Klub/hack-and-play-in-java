9.1 Give related data a shape

A space parcel has a name and a weight. Two unrelated variables can accidentally describe different parcels. A record gives the pair one shared shape, so a label can travel through the program as one value.

A type and one concrete parcel

void main() {
    Parcel parcel = new Parcel("Moon rock", 4);
    IO.println("Item: " + parcel.name());
    IO.println("Weight: " + parcel.weight());
}

record Parcel(String name, int weight) {
}

Open code/ParcelLabel.java and run it. The record declaration describes a new type named Parcel. Its components are name, a String, and weight, an int. The empty braces are correct: Java supplies the basic construction and reading operations.

The expression new Parcel("Moon rock", 4) constructs one object with those component values, in declaration order. Parcel before the variable name says what kind of value parcel holds. Defining the record alone creates no parcel and prints nothing.

An accessor reads a component: parcel.name() returns the name; parcel.weight() returns the number. These are method calls, so keep the parentheses. A record has no automatic operation for replacing a component. To describe changed data, construct another record.

Predict before changing it

If the constructor receives "Ice" and 0, the label prints Item: Ice and Weight: 0. What changes if only the text becomes "Hot ice"? Only the Item line; the two components have separate roles.

Task: stop losing the cargo data

Open code/CargoLabel.java. It reads three answers but constructs an empty replacement cargo. Construct Cargo from the answers, then calculate total weight from its count and unitWeight accessors. Keep both printed lines and their wording.

For Star seeds, count 3 and unit weight 4, expect Star seeds: 3 pieces and Total weight: 12. A count of 0 must give total 0, even with unit weight 8. Use nonnegative whole numbers; input validation is not this task.

Hint 1: follow the values

Match each constructor argument to one component in the declaration. Reusing the same type does not make the count and weight interchangeable.

Hint 2: check the units

A unit weight is the weight of one piece. Multiplying it by the piece count gives the weight of the whole cargo. Read both numbers from cargo.

Next, construct several objects of the same type and investigate which values belong to each one.
