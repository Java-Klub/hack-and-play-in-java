9.2 One description, several objects

A map needs both a starting point and an arrival point. They share the same shape but need not share their coordinates. Think of a type as a description and each constructed object as one concrete set of data.

Construction takes the current values

void main() {
    int x = 2;
    Point first = new Point(x, 3);
    x = 8;
    Point second = new Point(x, 3);
    Point copy = new Point(2, 3);
    IO.println("First: " + first.x() + "," + first.y());
    IO.println("Second: " + second.x() + "," + second.y());
    IO.println("Same values: " + first.equals(copy));
}

record Point(int x, int y) {
}

Open learn/examples/09/MapSnapshots.java. The first constructor receives the current value of x, which is 2. Later assignment changes the local variable x to 8. It does not reach backwards into the Point already constructed. Its component remains 2.

The next new Point uses 8 and 3. The declaration of Point is written once, but construction can happen many times with different arguments. This is the same value-passing principle you used with method parameters, now used to build data.

Records supply equals for comparing component values. first.equals(copy) is true because both points have x equal to 2 and y equal to 3. This asks whether the data match, not whether you wrote the same variable name. For text components, record equality compares their content too.

Predict a new snapshot

Set x to 2 again before constructing second. Both printed points are then 2,3. Changing x afterwards still changes neither point. What would first.equals(second) return? True, because their component values match.

Task: leave a checkpoint behind

Open learn/practice/09/Checkpoint.java. Preserve start and construct finish two columns to the right and one row up: add 2 to x and subtract 1 from y. Use start accessors so the new point is calculated from the saved position.

For input 2 and 3, Start must remain 2,3 and Finish must become 4,2. Back at start must be false. Also test -2 and 0: expect start -2,0 and finish 0,-1. Negative coordinates are allowed; do not clamp them.

Hint 1: a changed position needs new data

Assigning start to finish does not calculate a movement. Construct a Point with the two calculated component values.

Hint 2: preserve the checkpoint

Do not replace start while calculating finish. The two output lines let you check both the movement and preservation of the original.
