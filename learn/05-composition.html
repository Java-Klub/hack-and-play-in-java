5.5 Combine small referees

A spellbook has three jobs: clean the input, recognise an allowed spell, and choose an effect. Each part can have its own name and return a result to the next one.

From an answer to an effect

Open learn/examples/05/SpellPipeline.java. Run the program twice: first enter RED with spaces around it, then enter the unknown spell green on the second run.

void main() {
    String input = IO.readln("Spell: ");
    String spell = clean(input);
    IO.println("Effect: " + effect(spell));
}

String clean(String input) {
    return input.strip().toLowerCase(Locale.ROOT);
}

boolean isKnown(String spell) {
    return spell.equals("red") || spell.equals("blue");
}

String effect(String spell) {
    if (!isKnown(spell)) {
        return "Fizzle";
    }
    return switch (spell) {
        case "red" -> "Fire";
        default -> "Ice";
    };
}

Spell:  RED 
Effect: Fire

The main method handles reading and displaying. The method clean returns the cleaned text. The method effect asks isKnown for a boolean; if the spell is unknown, it returns Fizzle. Otherwise, it chooses an effect. The default branch in this switch now means blue, because all other possibilities were rejected before it.

This is method composition. Follow one call: effect receives red → calls isKnown(red) → receives true → skips the rejection → chooses Fire → returns it to main. Returning true from isKnown ends only isKnown; effect still has work to do.

The spell calculation does not read or print anything. To try it without asking the player for input, temporarily replace the body of main with the single statement IO.println(effect("blue")); and expect Ice. Keep the helper method definitions. Then restore the original body of main. The method effect receives text that has already been cleaned; for any other input, use clean first. Each method makes a small, specific promise.

Task: build the arena referee

Open learn/practice/05/ArenaReferee.java. The main method is complete. For now, the referee approves absolutely everything.

Complete three methods that work together. The method clean returns text with leading and trailing spaces removed and all letters in uppercase. The method cost receives a cleaned command: JUMP costs 3, DUCK costs 1, and an unknown command has a cost of 0. The method verdict first uses clean and cost; it returns UNKNOWN for an unknown command, TIRED for too little energy, and GO otherwise.

Reading and printing stay only in main. The method verdict uses both helpers instead of copying their rules. Try energy values of zero or more. Accepting a move does not subtract energy here: the program judges one proposed move.

JUMP2TIRED

DUCK0TIRED
wait or an empty line20UNKNOWN
Hint 1: the path of the values

The method verdict receives the original move, stores the result of clean under a new name, and only then passes this cleaned text to cost. The resulting cost is enough for the two rejection conditions.

Hint 2: the order of rejection

A cost of 0 means an unknown command, not a free move. First reject an unknown command, then compare the energy with the cost. Energy equal to the cost is allowed.

Frogs need a direction, not a separate copy of the calculation

In L03/M12_ToadsAndFrogs.java, toads have the species number 1 and move right; frogs have number 2 and move left. The board starts like this:

positions:  0 1 2 3 4 5 6
creatures:  T T T . F F F
toads:      →
frogs:      ←

The method direction returns the sign of the movement. The method destination receives origin (the internal position), distance (a positive step or jump length), and piece (the creature's species). It should call direction and return a candidate destination position. For example, origin 4, distance 1 and piece 2 should give 3. Origin 2, distance 1 and piece 1 also gives 3; so does a frog jumping a distance of 2 from position 5.

Both methods only calculate. The supplied move checks for an empty square, a legal jump, and the board edges, then performs the actual move. Do not change the board. The on-screen positions are numbered 1 to 7 for the player: at the start, pressing 5 asks the first frog to move into the gap. R restores the starting position. Select the check in L03/Check.java.
