4.3 Combine rules

Two different passes are valid for the laboratory. Either one is enough, but you also need energy, and the door must not be locked.

Or, and, not

Open learn/examples/04/TwoKeys.java.

void main() {
    String badge = IO.readln("Badge: ").strip();
    int energy = Integer.parseInt(IO.readln("Energy: ").strip());
    boolean trusted = badge.equals("SUN") || badge.equals("MOON");
    boolean enough = energy >= 3;
    boolean locked = false;
    boolean enter = trusted && enough && !locked;
    IO.println("Access: " + enter);
}

Badge: SUN
Energy: 3
Access: true

|| is OR: at least one side must be true. && is AND: both sides must be true. ! is NOT: it changes true to false and false to true.

falsefalsefalsefalse
falsetruefalsetrue
truefalsefalsetrue
truetruetruetrue

The variable trusted answers one question about the pass. The variable enough answers the energy question. !locked means the door is not locked. The final expression needs all three conditions to be true.

When mixing OR and AND, parentheses or named intermediate results such as trusted help. AND takes priority over OR; parentheses let you choose your own grouping. Write OR with two vertical bars, and AND with two & symbols.

Task: find the false permission

Open learn/practice/04/LabPermit.java. Try the outsider's pass STAR and energy 9. The program grants access even though that pass does not belong to the laboratory.

Fix the rules: BLUE or GOLD is valid, energy must be at least 3, and locked must be false. All three requirements apply at the same time. The result stays as one Access message.

Check the last case by temporarily changing the initial value of locked to true in the source. Then put it back to false. This value is not read from Output when the program runs.

Hint

Separate “one of two passes” from “all requirements for entry”. The energy comparison must also accept the lowest valid value. In the final expression, use the opposite of locked.

When is the second question asked at all?

Java evaluates AND and OR from the left. In A && B, it skips B after a false A: the result must already be false. In A || B, it skips B after a true A: the result must already be true. This is called short-circuit evaluation.

You can try this short fragment inside main. Division by zero makes no sense here, but the second question is never evaluated:

int pieces = 0;
boolean exact = pieces > 0 && 12 % pieces == 0;
IO.println(exact);

It prints false. With pieces equal to 3, the result is true; with 5, it is false. Reversing the two questions would start with invalid division when the value is zero. Order can protect the next calculation.

Hack a lock or fix a judge

  • L02/M07_Codebreaker.java: add a service code as the task describes. An ordinary correct guess must still work, and other wrong guesses must stay wrong. Find the question that decides victory; keep the supplied four-digit validation.
  • L02/M08_PokerDice.java: a full house needs both a triple and a pair. The supplied action receives two numbers: largestGroup is the size of the largest group of matching dice, and pairs is the number of groups containing exactly two dice. Use these numbers to create two boolean results and a combined verdict. A triple on its own should remain a lower-scoring win. Scoring help in the window explains the game rules.

Both tasks are checked by L02/Check.java. In Program Arguments, select the file you are working on.
