11.5 Same start, same experiment

A random maze may produce a strange route worth showing someone else. A seed lets you replay the same experiment rather than describing it from memory. Reproducibility is useful both for sharing challenges and for investigating an unexpected program result.

A seed starts a sequence; it is not every answer

void main() {
    int[] first = sequence(42);
    int[] replay = sequence(42);
    IO.println("First: " + Arrays.toString(first));
    IO.println("Replay: " + Arrays.toString(replay));
    IO.println("Same: " + Arrays.equals(first, replay));
}

int[] sequence(int seed) {
    Random random = new Random(seed);
    int[] values = new int[4];
    for (int i = 0; i < values.length; i++) {
        values[i] = random.nextInt(10);
    }
    return values;
}

Open learn/examples/11/ReplayNumbers.java. New Random(seed) starts a generator from a specified initial state. The constructor accepts a long integer; our int seed is automatically widened to that type without losing its value. No special seed value is required for the generator to work.

One generator is created before the loop. NextInt(10) supplies a value from 0 through 9 and advances its state. The four calls therefore continue one sequence. Arrays.toString displays the elements; Arrays.equals checks their values rather than array identity.

Calling sequence(42) twice creates two generators with the same start and the same requests, so both produce [0, 3, 8, 4]. A seed alone is not the whole recipe: changing bounds, adding a random call or rearranging calls can change later outcomes.

Predict a restarted generator

If a new Random(42) were created before each individual sample, all four values would be 0. Why? Every generator would make only the first request from the same starting state. Which value would the nextInt(10) call after the first one return with one reused generator? 3.

Task: repair the repeatable door route

Open learn/practice/11/ReplayDoors.java. Each route should use one generator for four successive door numbers from 1 to 6. Repair its lifetime so every route restarts from the supplied seed, but individual doors continue that route’s sequence. Preserve both main calls.

For seed 42 expect [3, 4, 1, 3]; for seed 0 expect [1, 5, 2, 6]. Both must report Replay matches: true. A repeated door within a route is allowed. A different seed need not produce different values at every position.

Hint 1: locate the restart

Find where new Random runs. Ask whether it should run once per route or once per door.

Hint 2: keep the state local to one route

Create the generator inside route but outside its loop. Sharing one generator across both route calls would continue rather than replay the sequence.

You can now choose between unchanged data snapshots, growing collections and stateful objects. Next, use those tools to organise interactive programs whose events happen over time.
