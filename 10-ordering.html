10.4 Pass an ordering rule

A spell list might put the shortest names first, with alphabetical order breaking ties. The sorting machinery already exists. Your job is to describe which of two names should come first, so Java can ask that question repeatedly.

A small function passed as a value

void main() {
    List<String> names = new ArrayList<>(List.of("owl", "a", "bear"));
    Comparator<String> byLength = (left, right) ->
        Integer.compare(left.length(), right.length());
    names.sort(byLength);
    IO.println(names);
}

Open code/ShortNamesFirst.java. A lambda describes behavior without declaring a separate named method. In (left, right) -> expression, the two names are parameters; the arrow separates them from the calculated result. Writing the lambda does not yet compare particular names.

Comparator<String> specifies the required behavior: accept two Strings and return an int. Java infers the parameter types. Sort calls this comparator many times. A negative result puts left first, a positive result puts right first, and zero means they tie under this rule.

Integer.compare compares two int values and returns the appropriate sign. It avoids assuming every difference is safely represented by subtraction. List.sort rearranges the mutable list itself; it does not return a sorted replacement. Use the ArrayList copy, not an unmodifiable List.of list.

Predict one comparison

Comparing "a" with "bear" by length gives a negative result, so a comes first. Comparing "owl" with "ant" gives zero. Does this rule alone prefer ant? No; it has not defined an alphabetical tie-break.

Task: give equal lengths a clear order

Open code/SpellOrder.java. Complete compareSpells: compare lengths first; only when equal, compare the full names alphabetically. String.compareTo supplies negative, zero or positive by text order. The supplied lowercase English names make that order easy to inspect.

Expect [a, ant, bee, owl, eagle], then Tie: true and Same: 0. Equal text must tie. The prepared lambda passes both real arguments to your method: preserve that connection. Do not hard-code the final list or return only the answer for bee and ant.

Hint 1: one comparison has priority

Save the length comparison. A nonzero result already decides; do not overwrite it with alphabetical order.

Hint 2: check the sign in both directions

Ant before bee needs a negative result; bee before ant needs a positive one. The exact positive number is unimportant.

Next, reuse lambdas for selecting and transforming elements without rearranging the original list.

A colour can be a key too

Picture games often store a colour as one int from getRGB(). This key is not a brightness ordering. A smaller signed RGB key means ordinary integer comparison, including negative values, rather than comparing lightness. When two colours share a frequency, apply the second criterion only after the first ties. An empty map needs an explicitly defined result.

Practise in a game

  • PhotoRemixLab · L09/M05_PhotoRemixLab.java
    In PhotoRemixLab choose the least frequent positive count, breaking ties with the smaller signed RGB key. The visible highlight must use that actual colour.
