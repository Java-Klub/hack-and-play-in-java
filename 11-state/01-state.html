11.1 An object remembers a change

A score counter should remember every award. Records gave you new snapshots; now you need one object whose data changes over time. A class can hold that changing state and provide methods that update it.

A field lasts beyond one call

void main() {
    Counter score = new Counter();
    IO.println("Before: " + score.points);
    score.add(3);
    score.add(4);
    IO.println("After: " + score.points);
}

class Counter {
    int points = 0;

    void add(int amount) {
        points = points + amount;
    }
}

Open 11-state/P01_ScoreCounter.java. Class Counter declares a type. Its field points belongs to each Counter object and starts at 0. Unlike a local variable inside add, the field remains after that method returns. It is not recreated for every award.

New Counter() constructs an instance, one concrete object of that class. Because we have not declared a constructor, Java supplies a parameterless one here. Counter’s braces contain its fields and methods; they are separate from the surrounding main method.

Score.add(3) changes that object’s points from 0 to 3. The next call reads 3 and stores 7. Access score.points reads the field directly; no parentheses are used because this is data access, not a method call such as a record accessor.

Predict one more call

Add 2 after the prepared calls and After becomes 9. What if you instead construct a new Counter before printing? That new object starts at 0; constructing it does not transfer the old score.

Task: remember the best combo

Open 11-state/P02_ComboMeter.java. A hit increases the current streak by one and updates best only when the new streak beats it. A miss resets streak to 0 but must preserve best. Complete both operations; do not change the prepared sequence.

Two hits, a miss and one hit must print Current: 1 and Best: 2. Try another hit: Current becomes 2 and Best stays 2. A third consecutive hit makes both 3. A miss at the beginning leaves both at 0.

Hint 1: separate current and history

Update the current streak first. Then compare it with best. A local replacement variable would not preserve the record between calls.

Hint 2: a miss is not a full reset

Only the current streak ends. Erasing best would lose the very history this object is meant to remember.

    Complete both roll effects in Pig: one loses the current turn total and passes play; other valid rolls add points. An invalid die changes nothing.
  • MancalaKalah · 11-state/P04_MancalaKalah.java
    Repair MancalaKalah's reset of the actual player to player one. Restoring stones and clearing the result must continue working.
  • SlidingTiles · 11-state/P05_SlidingTiles.java
    SlidingTiles counts real moves during shuffling. Reset the player's move count after setup, without changing the creation of solvable boards.
  • MiniCrossword · 11-state/P06_MiniCrossword.java
    MiniCrossword repeatedly adds an old answer count. In command separate a fresh recount from stored history; three answers must not win prematurely.
