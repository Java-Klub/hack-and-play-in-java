11.4 Chance proposes, a rule decides

A die makes a small battle uncertain. The random roll and the rule converting it into damage are different jobs. Keeping them separate lets you check the rule for every face instead of waiting for a lucky test run.

Ask one generator for the next value

void main() {
    Random random = new Random();
    int die = roll(random);
    IO.println("Roll: " + die);
    IO.println("Damage: " + damage(die));
}

int roll(Random random) {
    return random.nextInt(1, 7);
}

int damage(int die) {
    if (die <= 2) {
        return 0;
    }
    return die - 2;
}

Open 11-state/P17_DiceDamage.java and run it several times. New Random() creates a pseudorandom generator: an object that produces a sequence of apparently random values. It keeps internal state, so the next request continues that sequence rather than repeating a fixed answer.

NextInt(1, 7) includes the lower bound 1 and excludes the upper bound 7: the possible results are 1 through 6. Bounds matter. NextInt(1, 6) would never roll 6. Repeated rolls may be equal; randomness does not promise a different result every time.

The generator is passed as a parameter to roll. The rule damage receives only the resulting int: faces 1 and 2 miss, higher faces deal face minus 2. This rule does not need Random, input or printing, so you can call it with deliberately chosen arguments.

Predict the rule, not the roll

If Roll is 5, Damage must be 3. What damage belongs to 2? Zero. You cannot honestly predict the next roll from this screen alone, but you can predict the correct reaction to any given roll.

Task: roll a real pair

Open 11-state/P18_DoubleDice.java. Upgrade rollPair from one die to the sum of two separate six-sided rolls. Ask the supplied generator twice, store both face values, and return their sum. Do not create another generator inside the helper.

Every result must lie from 2 to 12. Equal faces are allowed. A single uniform choice from 2 to 12 is a different experiment: with two dice, 7 has more combinations than 2. A short run need not display every possible sum.

Hint 1: count random requests

Doubling one rolled face would produce only even totals. Two calls supply two successive samples, which can also be equal.

Hint 2: preserve the generator

Receive the generator in the parameter and reuse it. The caller controls its lifetime; the helper only asks for the samples it needs.

Next, give a generator a starting seed so a surprising sequence can be replayed exactly and shared as a reproducible puzzle.
