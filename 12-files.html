12.4 Read data from a real file

Give a program a message that survives after it ends. Run the example once. It prints the exact path it will read, then reports that the file is missing. Create a plain UTF-8 text file at that displayed path, put Moon gate inside, and run again.

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

String readMessage(Path file) throws IOException {
    return Files.readString(file).strip();
}

void main() {
    Path file = Path.of("message.txt");
    IO.println("Reading " + file.toAbsolutePath());
    try {
        IO.println("Message: " + readMessage(file));
    } catch (IOException failure) {
        IO.println("Cannot read message.txt.");
    }
}

Path.of describes a filesystem location; it does not create or open a file. A relative path starts from the running program’s current working folder, not automatically from the folder containing its source.

Use the printed absolute path to find the right folder; you do not need to change an IDE setting. Path.of(".").toAbsolutePath() can also show the working location. A file manager may hide extensions: check the real filename.

Files.readString reads the complete file as UTF-8 text and closes its internal resource. It preserves line breaks; strip removes only the outer whitespace afterwards. An empty file is readable and supplies empty text.

IOException is a checked exception. A helper that lets it travel to its caller declares throws IOException; a caller must catch it or declare it too. The declaration warns about a possible failure. It does not throw anything by itself.

Predict a missing file

With Moon gate in the file, the example prints Message: Moon gate. Rename the data file and run again: the catch prints Cannot read message.txt.. What happens with an empty file?

Task: respect the selected filename

In code/TargetFile.java, repair readTarget to read its filename parameter and return stripped uppercase text. Run once with each filename and create target.txt containing north and other.txt containing south at their displayed paths. A blank reply selects target.txt; replying other.txt must produce Target: SOUTH.

Reading must leave both files unchanged. Try a missing filename and an empty readable file too. Do not silently substitute a different file when the requested one cannot be opened.

Hint 1: follow the parameter

Build the Path from filename. The caller has already chosen the default.

Hint 2: keep returned text

Chain the known strip and toUpperCase operations onto the actual read result.

When a file is read line by line

A reader keeps an open resource between reads. try-with-resources closes it even when reading fails. readLine removes the line ending and returns null only at the end; an empty line is the empty String.

String readFirst(Path file) throws IOException {
    try (var reader = Files.newBufferedReader(file,
            java.nio.charset.StandardCharsets.UTF_8)) {
        String line = reader.readLine();
        return line == null ? "" : line;
    }
}

The parentheses after try introduce the resource. Use this ownership rule for file streams and audio streams too: the code that opens a resource must arrange its closing.

A sound file is also an owned resource
float sampleRate(Path file) throws IOException,
        javax.sound.sampled.UnsupportedAudioFileException {
    try (var sound = javax.sound.sampled.AudioSystem.getAudioInputStream(file.toFile())) {
        return sound.getFormat().getSampleRate();
    }
}

This helper reads a sound format without playing it. The return value is obtained before the stream closes. UnsupportedAudioFileException is another checked failure for an unrecognised format; the caller must handle or declare it alongside IOException.
