5.1 Give your own step a name

A drone can turn on its lights and flash them. You want to change its show by combining short commands instead of copying the instructions inside them.

A definition waits; a call starts it

Open 05-methods/P01_DroneShow.java. Before running the program, count how many times FLASH will appear.

void main() {
    wake();
    flash();
    flash();
    IO.println("Show finished");
}

void wake() {
    IO.println("Drone awake");
    IO.println("Lights ready");
}

void flash() {
    IO.println("* FLASH *");
}

Drone awake
Lights ready
* FLASH *
* FLASH *
Show finished

wake and flash are our methods: named parts of a program. The “supplied actions” you have used so far are methods too. A definition describes what a method does; a call asks it to run.

NotationWhat it means
void flash() { ... }Define the method flash. Its body is made up of the statements between the braces.
flash();Call it right here. The parentheses belong to the call; the semicolon ends this statement.
voidThis call does not provide a result value. It can still do something, such as print a message.
()We are not passing any values to this method.

When the program starts, Java begins in main. It reaches wake(), runs its two print statements, and returns to the next statement in main. It runs each call to flash in the same way. The definitions below main do not run by themselves. Their order in the file does not determine the order of the show.

Write new methods alongside main, after its closing brace. Do not put one method definition inside another method's body.

Task: tidy up the alarm without changing its sound

Open 05-methods/P02_AlarmRemix.java. The alarm works, but the same pair of print statements has been copied twice.

Create a method void alarm() alongside main that prints Intruder! and Lights red. Replace both copies of these two lines in main with a call to alarm(). Keep the door messages between them in their original places.

The full output should stay the same: alarm, door A, alarm, door B. This time, the goal is refactoring: changing the structure while keeping the same behaviour.

Hint: which braces go where?

The methods main and alarm each have their own pair of braces. Four statements remain in main: two calls and two print statements. The body of alarm contains two print statements.

One change, two places

After the refactoring, change Lights red to Lights purple only inside alarm. Both alarms must change when you run the program. Add a third locked door to main with another call. You do not need to add anything inside alarm for the third door.

Question: what does a definition do on its own?

If you remove all calls to alarm from main, the definition stays in the file, but no alarm is printed. Make a prediction, try it, and then restore the calls.

You can now create a method without parameters, call it several times, and follow the return to the caller's next statement.
