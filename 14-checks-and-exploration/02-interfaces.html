14.2 Compose objects by their behaviour

A caller can ask for a greeting without knowing which greeting object it receives. An interface names the behaviour the caller needs. A record can provide that behaviour while carrying its own small piece of data.

14-checks-and-exploration/P08_Example_GreetingRoles.java

/// # Worked example · 14.2 Compose objects by their behaviour
/// Lesson: 02-interfaces.html

interface Greeting {
    String message(String name);
}

record Welcome(String prefix) implements Greeting {
    public String message(String name) {
        return prefix + ", " + name + "!";
    }
}

String greet(Greeting greeting, String name) {
    return greeting.message(name);
}

void main() {
    Greeting greeting = new Welcome("Hello");
    IO.println(greet(greeting, "Nova"));
    IO.println(greet(new Welcome("Welcome"), "Mika"));
}

Greeting declares a method signature ending in a semicolon: implementations must provide message with one String parameter and a String result. There is no body in this declaration.

implements connects Welcome to that contract. Its implementation method is public because interface operations are public. The record still supplies its familiar constructor and prefix accessor. The interface itself cannot be constructed with new.

A variable declared as Greeting can refer to a Welcome. Calling message uses the implementation of the actual object. The greet helper depends on the promised behaviour rather than on one concrete record type.

Predict another implementation value

The first call returns Hello, Nova!; the second returns Welcome, Mika!. What would greet(new Welcome("Ahoy"), "Sol") return? The caller needs no new branch for that prefix.

Task: assemble two word rules

Finish 14-checks-and-exploration/P09_Task_RuleGate.java in two places. Both must accept only when both contained rules accept the same word. Then wire gateRule to a Both containing Minimum(4) and NotWord("robot").

After the caller strips outer spaces, moon is allowed, cat is too short, and robot is forbidden regardless of letter case. Empty input is too short. Keep the individual rules reusable; do not put one combined special formula inside main.

Both contains two Rule references: this is composition. It delegates questions to the contained objects and combines their answers. The contained rule could itself be another Both, allowing a larger rule without changing the caller.

Hint 1: both is stronger than either

Select the boolean operator that refuses a word when either contained rule refuses it.

Hint 2: make the running program use the composition

Construct both component records inside the new Both returned from gateRule. A repaired unused Both cannot change the windowless input program.

Restore a temporary role with finally

Sometimes an experiment temporarily replaces a stored role. Add this field and helper alongside Greeting, Welcome and greet from the worked example:

Greeting active = new Welcome("Hello");

String preview(Greeting temporary, String name) {
    Greeting previous = active;
    try {
        active = temporary;
        return greet(active, name);
    } finally {
        active = previous;
    }
}

The first call below returns Ahoy, Nova!; the second gives Hello, Nova! because active refers to the original Welcome again. The return value is computed before finally restores the old reference. Replace the two print calls in the example’s main to try this:

IO.println(preview(new Welcome("Ahoy"), "Nova"));
IO.println(greet(active, "Nova"));

Finally runs when control leaves try normally, through return, or because of an exception. It does not catch that exception: after cleanup the failure still travels to the caller, which can catch it. Keep restoration in finally so both successful and failed experiments restore the same role.

Next you will use a different kind of interface: a deliberately closed family of data variants that a switch can inspect exhaustively.
