5.4 How far does a name reach?

A helper claims it has reduced the drone's energy. After the call returns, main still sees the original number. Two identical names do not necessarily mean one shared variable.

A parameter belongs to one call

Open code/ChargeCopy.java. First, predict both numbers:

void main() {
    int energy = 3;
    drain(energy);
    IO.println("In main: " + energy);
}

void drain(int energy) {
    energy = energy - 1;
    IO.println("In drain: " + energy);
}

In drain: 2
In main: 3

The call drain(energy) passes the value 3. The parameter energy in drain is a separate local variable for this call. The subtraction changes this parameter; the variable energy in main stays at 3. Matching names in different methods are a coincidence, not a connection.

Stepenergy in mainenergy in drain
Before the call3The call has not started yet.
After passing the argument33
After the subtraction in drain32
After returning3The call has finished.

Scope determines where a name can be used. Parameters are available inside their method's body. A variable created in main is not available inside drain. A variable created inside an if block stops being available when that block ends; you cannot read it later in the surrounding block.

Change the name of drain's parameter and its two uses to charge. The output must stay the same. Renaming only the parameter without changing its uses would leave an unknown name.

Task: the med kit did not heal anything

Open code/MedKit.java. With health 4, heal produces a result, but main throws it away. The method also fails to prevent health from exceeding its maximum.

Store the value returned by heal back into health in main. Inside heal, add a limit: the med kit adds 3, but the result must not exceed 10. Do not add any print statements to heal. Try starting health values from 0 to 10.

Health: 4
Health after kit: 7

Also try 0 → 3, 7 → 10, 8 → 10 and 10 → 10. Then add a second use of the med kit just before the final print statement. Starting from health 4, two uses should give 10. Each call must receive the result of the previous one.

Hint: a result is not an automatic assignment

A call on a line of its own does run, but its returned value is not stored anywhere. Use the same assignment of a result as in the price example. The limit of 10 belongs inside heal so that it applies to every caller.

The same rule applies when replacing text

Assigning cleaned or different text to a parameter of type String does not overwrite the caller's variable either. Both names may originally refer to the same text, but assigning different text to one of them does not change the other. You need to return the cleaned text and use it. You have already seen this with strip, which did not change the original text.

Our small methods have values inside their parentheses. In the supplied games, you will also see state outside methods, shared by their calls. This is not the same as a local parameter; you will return to it in more detail when working with objects and game state.

Add a reward for an SOS combination

In L03/M09_SOS.java, change gainedPoints. The parameter before is the total number of SOS lines before the move; after is the total number after it. For example, before 4 and after 6 means two new lines, not six.

Store the number of new lines in a local variable. One new line gives one point; two or more give twice the number of new lines. No new line gives 0. The method only returns a reward: it does not change the board, the score, or the player. For (4, 6), expect 4; for (4, 5), 1; for (4, 4), 0. Select the check in L03/Check.java.

You can now distinguish local values with the same name and deliberately use the result of a helper method.
