5.2 Send values to a method

Every place on a map has its own name and position. One method can prepare all the labels if you give it the right values on each call.

Names for roles and actual values

Open code/MapLabels.java. Predict both lines.

void main() {
    mark("Portal", 2);
    mark("Dragon", 7);
}

void mark(String name, int position) {
    IO.println(name + " at " + position);
}

Portal at 2
Dragon at 7

String name and int position are parameters in the definition. They name the values the method receives when called. In contrast, "Portal" and 2 are arguments: the actual values passed in the first call.

Callname inside markposition inside mark
mark("Portal", 2)Portal2
mark("Dragon", 7)Dragon7

A comma separates the roles and the values being passed. Their order, number and types must match. A parameter's name does not look up any information by itself. On the next call, it receives new values.

An argument can also be a variable or a calculation: mark("Exit", 2 + 3); passes position 5. In the definition, you write a type and a name; in a call, you write only the values or expressions that provide them.

Task: the portals take passengers the wrong way

Open code/PortalRoutes.java. Enter Moon for Start and Mars for Finish. Instead of a journey there and back, you see Mars → Mars twice.

Fix the first call so that it goes from start to finish. The second should go back. Inside route, fix the print statement to use both parameters in their correct roles. Do not hard-code the planet names in the output.

Start: Moon
Finish: Mars
Moon -> Mars
Mars -> Moon

Also try Red Planet and Club Base. Do the full names and the correct direction stay intact? Both arguments have the type String, so the compiler cannot detect that you have swapped them: you are responsible for what the roles mean.

Hint: put the values in a small table

For each call, write down the value received by from and the value received by to. Their order is set by the call, not by whether an argument has the same name as a parameter.

Ask the number machine a question

Open L02/M11_NumberMachine.java. Run it and watch the pairs of results. In main, add another call to compare with a number of your own that helps reveal the machine's rule. For now, keep the reference machine folded and leave imitation alone.

The method compare has a parameter named number, so compare(-3); prepares one experiment with negative three. You do not need to change its body for each new input. Write down your prediction and the actual result; in the next lesson, you will build your own imitation.

You can now tell a parameter from an argument and work out which values a method receives in a particular call.
