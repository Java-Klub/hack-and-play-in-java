4.4 Stop an illegal move in time

The player enters the cost of a move. We want to subtract energy only when the move is allowed. A refused attempt must preserve the original energy.

Refuse first, then change

Open 04-decisions/P12_EnergyTurn.java. Try cost 0, then 6, then 3.

void main() {
    int energy = 5;
    int cost = Integer.parseInt(IO.readln("Move cost: ").strip());
    if (cost < 1) {
        IO.println("Cost must be positive");
        IO.println("Energy: " + energy);
        return;
    }
    if (cost > energy) {
        IO.println("Not enough energy");
        IO.println("Energy: " + energy);
        return;
    }
    energy = energy - cost;
    IO.println("Move accepted");
    IO.println("Energy: " + energy);
}
Move costDecisionEnergy at the end
0Cost must be positive5
6Not enough energy5
3Move accepted2

return; inside main immediately ends this call. That is why refusal prevents both the subtraction and the message accepting the move. Main has void in its declaration, so we do not pass a value after return here.

This kind of early refusal is called a guard clause. It rules out forbidden cases at the start. After both guards, only a valid move remains, so you can subtract the cost directly.

Each fresh run of this small program sets energy back to 5. One run makes one attempt.

Task: the move was refused, but energy disappeared

Open 04-decisions/P13_SafeMove.java. Enter cost 6. The program announces both refusal and acceptance, and shows negative energy. Find the first line where it changed the stored state too soon.

Move the subtraction after the decision. Refuse a cost below 1 or above the available energy, print Move refused and the unchanged energy, then end main. For a valid move, subtract the cost and print Move accepted with the remaining energy.

Also check -1, 0, 1 and 5. The last two costs are valid and leave energy 4 and 0. A negative cost must not add energy.

Then change the initial energy to 8 and enter cost 6: the move must succeed and leave energy 2. With cost 9, all 8 units must remain. Finally, restore the initial energy to 5.

Hint 1: a message is not enough

If only runs its own block. After the block ends, execution continues on the next line. Where do you need to end the whole call so that the acceptance message is never printed?

Hint 2: preserve the original value

Compare the cost with energy before subtracting it. Print the unchanged energy inside the refusal block. Keep the subtraction and both success messages after that block.

A supplied action can return a verdict

In another game, you do not end the whole main, only one call to a judge:

boolean accepts(int cost) {
    if (cost < 1) {
        return false;
    }
    return true;
}

The boolean before accepts says what type of result the caller receives. int cost names the number passed in. Return false ends this one call and hands back a refusal; the whole game can keep running. Similarly, an action with an int result can return a number, and one with a String result can return a message.

Guard the sea, then try a coach

  • 04-decisions/P14_SonarTreasureHunt.java: the window labels rows and columns 1 to 8. The supplied input code subtracts 1 from each label and passes numbers 0 to 7 to insideSea. You are fixing that internal question: both numbers must be within their own ranges. Buttons outside the map must not spend a probe. Guard all four edges, including the valid edge squares.
  • 04-decisions/P15_Nim.java: the game already runs against a bot. Watch its moves and complete your own coach. It should only recommend a number of stones, leaving the actual move and player switching to the supplied game. Return 0 for an empty pile. Here you will also use the remainder operation from earlier and practise reading someone else's code.

To check your work, open Check.java from the same folder as the game. In Nim, also notice whether asking for advice really left the current pile unchanged.

You can now refuse an illegal action before changing values, and distinguish ending main from returning one supplied action's verdict.
