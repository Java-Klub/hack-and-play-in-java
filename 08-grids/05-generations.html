8.5 Read the past; write the future

A light map changes in separate steps. Every cell should react to the same past. If you used an already updated cell to calculate its neighbour, part of the map would get a head start.

Two states instead of overwriting as you read

Open 08-grids/P23_SignalShift.java. Look at both rows before and after the shift.

void main() {
    boolean[][] old = {{true, false, false, false}, {false, true, false, false}};
    boolean[][] next = shiftRight(old);
    IO.println("Old");
    show(old);
    IO.println("Next");
    show(next);
}

boolean[][] shiftRight(boolean[][] old) {
    boolean[][] next = new boolean[old.length][old[0].length];
    for (int y = 0; y < old.length; y++) {
        for (int x = 1; x < old[y].length; x++) {
            next[y][x] = old[y][x - 1];
        }
    }
    return next;
}

void show(boolean[][] board) {
    for (boolean[] row : board) {
        IO.println(Arrays.toString(row));
    }
}

The method shiftRight creates a new array, next. Each place from column 1 onwards reads the value one column to its left in old. The first column remains false: this is the initial value in a newly created boolean array. A signal beyond the right edge disappears rather than wrapping left.

The rule never overwrites old. The main method can therefore still display the original rows after the calculation. Two different arrays separate reading the past from writing the future. This is called double buffering. A new name alone would not be enough, as you know from array copying.

Prediction: shift the result again

The first row becomes [false, false, true, false], and the second [false, false, false, true]. Pass the previous result into the next call. The original array still remains unchanged.

Task: light spreads one step at a time

Open 08-grids/P24_LightBloom.java. Initially, only the centre of the three-row map is on. Complete spread: in the next state, a cell is on if it is on now or has at least one active neighbour to the left, right, above or below. A diagonal is not enough.

Return a new array without changing the original. The main method performs the entered number of steps and shows both Start and After. For 0, only the centre remains. After 1, five true cells form a cross and the corners are false. After 2, all nine places are on. Try 0 to 3 steps.

The supplied isOn safely returns false outside the map. Use it for neighbours and the cell itself. This rule does not count neighbours as in the previous lesson: one true answer is enough. Combine the questions using OR.

Hint 1: separate input from output

Create a new boolean array with matching dimensions. Ask every question about now, and make every assignment into the new array.

Hint 2: check for a head start

If a corner is on after the first step, the calculation used information that was too new or included a diagonal. If Start changed, you are overwriting the past.

You can now choose a different cell rule for another world while keeping the same safe way of calculating its next steps.

Practise in a game

  • Slant · 08-grids/P25_Slant.java
    Repair Slant's snapshot including row copies. Restoration must work even after a winning move; a separate outer array is insufficient.
  • BinaryBalance · 08-grids/P26_BinaryBalance.java
    BinaryBalance shares answer rows with fixed clues. In copyBoard separate both levels so entering an answer cannot create a new locked clue.
  • RuleGarden · 08-grids/P27_RuleGarden.java
    Compute every cell of RuleGarden's nextRow from the same old generation. Compare with updating the row from left to right.
  • ForestFireSandbox · 08-grids/P28_ForestFireSandbox.java
    ForestFireSandbox should spread fire only from the previous generation's west neighbour. Old fire dies; prevent wrapping and double spread within a tick.
