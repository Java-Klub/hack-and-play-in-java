8.3 Ask the neighbouring cells

A sensor does not need to read the whole map: it cares about the immediate area around a selected place. First, you must define the neighbourhood. Do diagonal corners count? Does the cell itself count?

A small traversal around the centre

Open 08-grids/P10_Example_NeighbourScan.java. One means an active cell. Select the centre, 1, 1.

/// # Worked example · 8.3 Ask the neighbouring cells
/// Lesson: 03-neighbours.html

void main() {
    int[][] board = {{0, 1, 0}, {1, 1, 1}, {0, 1, 0}};
    int x = Integer.parseInt(IO.readln("X: ").strip());
    int y = Integer.parseInt(IO.readln("Y: ").strip());
    IO.println("Neighbours: " + neighbours(board, x, y));
}

int neighbours(int[][] board, int x, int y) {
    int count = 0;
    for (int dy = -1; dy <= 1; dy++) {
        for (int dx = -1; dx <= 1; dx++) {
            if (dx != 0 || dy != 0) {
                int nx = x + dx;
                int ny = y + dy;
                if (inside(board, nx, ny) && board[ny][nx] == 1) {
                    count++;
                }
            }
        }
    }
    return count;
}

boolean inside(int[][] board, int x, int y) {
    return x >= 0 && x < board[0].length && y >= 0 && y < board.length;
}

Nested loops visit every pair of offsets. For each dy from -1 to 1, the whole dx loop runs from -1 to 1. There are nine pairs; each describes a place relative to the centre rather than absolute coordinates.

The offset -1, 0 means one column to the left; offset 1, 1 means diagonally down and right. The pair 0, 0 identifies the cell itself, so we reject it. That leaves at most eight neighbours, including diagonals.

A neighbour's coordinates come from adding an offset to the centre. Before using them, we call inside. Because of AND, the cell is not read if its place is outside the map. A neighbour beyond an edge therefore does not count and does not wrap to the opposite side.

Prediction: the centre and top-left corner

The centre has four active neighbours; its own one does not count. Corner 0, 0 has three: right, below, and diagonally down-right.

Task: the sensor sees only four directions

Open 08-grids/P11_Task_CardinalSensors.java. Complete cardinal to count ones only to the left, right, above and below the place. Exclude diagonals and the cell itself. The supplied isOn also returns false outside the map.

Enter x and y from 0 to 2. For 1, 1, expect Neighbours: 2. For 0, 0, the answer is 1; for 2, 0, it is 2; for 0, 2, it is 0. These cases distinguish directions, a corner, and an empty neighbourhood.

Hint 1: draw four candidates

Write four coordinate pairs around the centre. Each candidate changes exactly one coordinate by one.

Hint 2: safe questions

Each true answer from isOn adds one to the result. The helper already handles edges; you do not need four copies of its internal rule.

Next, you will use row and column traversal to create a new pattern rather than only read prepared data.

Four ports in one number

Net stores north, east, south and west as flags with values 1, 2, 4 and 8. The number 5 means north and south because it contains 1 + 4. The expression 1 << direction creates a mask for direction 0 to 3. (ports & mask) != 0 then tests whether that port is present. A single & compares integer bits; double && combines boolean conditions. These forms are not interchangeable.

For a link, check both ends: the opposite direction is (direction + 2) % 4. Validate neighbour coordinates before reading its ports. Searching the whole network is supplied; your judge decides one local connection.
