11.3 Odmítnutí nesmí poškodit stav

Potápěč nemůže spotřebovat vzduch, který v nádrži není. Vrátit false po příliš velkém odečtení by bylo pozdě: nádrž by už obsahovala nemožnou hodnotu. Spolehlivý objekt ověří navrženou změnu před jejím provedením.

Slib, který přežije každou operaci

void main() {
    Tank tank = new Tank();
    IO.println("Use 3: " + tank.use(3));
    IO.println("Air: " + tank.air());
    IO.println("Use 4: " + tank.use(4));
    IO.println("Air: " + tank.air());
}

class Tank {
    private int air = 5;

    int air() {
        return air;
    }

    boolean use(int amount) {
        if (amount <= 0 || amount > air) {
            return false;
        }
        air = air - amount;
        return true;
    }
}

Otevři code/AirTank.java. Invariant (trvale platná podmínka) musí platit po dokončení každé operace. Nádrž začíná s air 5 a slibuje, že nikdy neklesne pod 0. Každá přijatá spotřeba musí být kladná a nejvýše rovna dostupnému vzduchu.

Private označuje air jako vnitřní detail implementace místo veřejného pole pro nesouvisející kód. Náš volající jej čte přes air() a o změny žádá přes use. Tuto hranici zachovej: přímá změna polí by obešla pravidla těchto metod.

Use nejprve ověří celý požadavek. Neplatné množství vrátí false před přiřazením. Platné množství se jednou odečte a vrátí true. Vystopuj volání: 3 ponechá 2; odmítnuté 4 ponechá úplně stejné 2, nikoli 0 ani -2.

Předpověz hraniční požadavek

Spotřeba přesně 2 v tuto chvíli uspěje a ponechá 0. A co spotřeba 0? Zde se odmítne, protože pravidlo výslovně vyžaduje kladné množství. Jiná pravidla jsou možná, ale volající a implementace se na nich musí shodnout.

Úkol: ochraň oba konce palivoměru

Otevři code/FuelTank.java. Fuel začíná na 5 a musí zůstat mezi 0 a kapacitou 10. Refill přijme jen kladné množství, které se vejde. Travel přijme jen kladnou cenu, která je dostupná. Ostatní požadavky odmítni pomocí false bez změny paliva.

Doplnění 3 a cesta 4 musí dát true, palivo 8, true, palivo 4. Doplnění 6 a cesta 0 musejí obě selhat a zachovat 5. Doplnění 5 a cesta 10 povoleně dosáhnou 0. Záporné požadavky rovněž musejí selhat beze změny.

Nápověda 1: ověřuj před zápisem

Před každé přiřazení dej ochrannou podmínku. Odmítnutá operace má zachovat původní hodnotu, nikoli ji dodatečně oříznout na hranici.

Nápověda 2: bezpečně změř volné místo

Porovnej doplňované množství s 10 - fuel. Tím odmítneš i obrovské kladné int bez přetečení při předčasném sčítání.

Příště necháš náhodu navrhovat výsledky a pravidla, která je vykládají, ponecháš oddělená a ověřitelná.
