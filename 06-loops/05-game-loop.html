6.5 Read the next move

One question is not enough for a command game. A terminal needs to read a line, process it, and show a result repeatedly. The player also needs a clear way to quit.

Reading inside repetition

Open 06-loops/P10_EchoTerminal.java. Enter ping, then something else, and finally q. Press Enter after each answer.

void main() {
    while (true) {
        String command = IO.readln("Command: ");
        if (command == null || command.equals("q")) {
            break;
        }
        if (command.equals("ping")) {
            IO.println("pong");
        } else {
            IO.println("Unknown");
        }
    }
    IO.println("Closed");
}

Using true with while always allows another round. A break on command q provides the way out. Reading is inside the body, so every round receives a new line. Reading only before the loop would keep processing the same answer.

The method readln can return null if input ends without another line. This is neither text nor an empty line. We first test command == null; short-circuit evaluation then prevents calling equals on null. Both q and the end of input leave the loop and print Closed.

Prediction: an empty line, then q

An empty line is not the end of input. You get Unknown, another prompt, and then Closed after q. Commands match exactly here: PING is not ping.

Task: a small drone controller

Open 06-loops/P11_DroneConsole.java. The loop and quitting work, but up and down do not change the altitude. Add these rules: up increases altitude by 1, and down reduces it by 1. Altitude must stay between 0 and 3.

After a valid move, print Altitude with its new value. An attempt beyond a boundary prints Blocked and leaves altitude unchanged. Any other command prints Unknown. Q is not q and counts as unknown; lowercase q ends with Landed and no further altitude message. End of input should quit the same way.

Try up, up, down, q: the altitudes should be 1, 2, 1. Entering down at the start should give Blocked. Four up commands should give 1, 2, 3, Blocked. One variable, altitude, must remember the state between rounds.

Hint 1: separate the rules

The exit is supplied first. Then distinguish a known direction and check its boundary. An unknown command must not change the state.

Hint 2: the step's result

A successful move changes altitude before printing. A rejected move prints only Blocked, not Altitude.

In the next chapter, you will store several values together. Instead of waiting for new input, a loop will visit individual places in prepared data.
