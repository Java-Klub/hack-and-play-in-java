6.3 Remember what has passed

A crew delivers fuel in three batches. You can read the numbers one at a time; to get the final result, you need to remember their sum rather than every individual answer.

The round counter is not the sum

Open 06-loops/P06_Example_FuelDeliveries.java. Enter 2, 0 and 4 in that order.

/// # Worked example · 6.3 Remember what has passed
/// Lesson: 03-accumulators.html

void main() {
    int total = 0;
    for (int delivery = 0; delivery < 3; delivery++) {
        int amount = Integer.parseInt(IO.readln("Fuel: ").strip());
        total = total + amount;
    }
    IO.println("Fuel total: " + total);
}

The variable total is an accumulator. It starts at zero, and each round adds another contribution. With these inputs, it holds 2, then still 2, and finally 6. Meanwhile, delivery only controls the three repetitions.

The variable total must be created before the loop: its value needs to survive the end of a round. If you created it inside, every round would start again from zero. In contrast, amount represents the delivery being read now, and is needed only inside one body.

The calculation total = total + amount; first reads the old total, adds amount, and only then stores the new result. It is not a mathematical equality that remains true forever. For these whole numbers, the shorter form total += amount; has the same effect.

Prediction: deliveries 5, 1, 2

The value of total becomes 5, 6 and 8. The final message is Fuel total: 8. Printing inside the loop would show three running totals instead of one final total.

Task: a noise survey

Open 06-loops/P07_Task_NoiseSurvey.java. It already reads three measurements, but the results stay at zero. During the traversal, collect two independent results: the sum of all measurements and the number of measurements that are at least 10.

Try measurements from 0 to 20. For 9, 10, 14, expect Total: 33 and Loud: 2. For three zeros, both results should be 0. For 10, 10, 10, the sum is 30 and the count is 3. Do not leave out a value of exactly 10.

Hint 1: two different questions

Every measurement contributes to the sum. Only a measurement that passes the condition contributes to the loud count, and it adds one rather than its measured value.

Hint 2: where to make the changes

Prepare both results before the loop, update them inside, and print them afterwards. Keep the three input reads.

The next traversal will not always process everything. Sometimes the first result you find is enough, and repetition can end early.
